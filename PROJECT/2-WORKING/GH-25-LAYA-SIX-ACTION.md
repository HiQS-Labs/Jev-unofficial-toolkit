## Recon map

```text
Pinned holdout + baselines
  -> receipt-local prepare (same state/instruction/options; untracked JSONL)
  -> Laya Router.route (must select english for all 100 rows)
  -> Router.load(exact local snapshot) -> Agent.system_one
       -> common.build_sequence (512 max / 192 head; right-side state truncation)
       -> DecisionModel marker logits -> temperature -> option probabilities
  -> create-only raw JSONL outside Git
  -> receipt-local summarizer
       -> jev.eval.metrics / confidence_table
       -> jev.guard.write_results
  -> independent aggregate verifier
  -> committed typed receipt without source text or local paths
```

Material seams:

- `laya/router.py::Router.predict` calls `route`, `load`, then `Agent.system_one`; default routing selects the English root checkpoint for English Latin text.
- `laya/agent.py::Agent.__init__` downloads one filtered snapshot, loads config/tokenizer/encoder/weights, and uses float32 on CPU. The public loader has no revision parameter, so the run will pre-download the exact revision and pass its local snapshot directory.
- `laya/agent.py::Agent.system_one` produces choice/probabilities/confidence and input-token usage. It rounds probabilities to four decimals; the receipt uses an explicit rounding tolerance and labels confidence according to Laya's own entropy-derived semantics, not as independently calibrated.
- `laya/common.py::build_sequence` places question/options before state with `max_len=512`, `head_max_len=192`, and default `truncate_left=False`; overlong state keeps its beginning. The scorer will record full/used state-token counts and the receipt will state how many rows lost late context.
- This repository already owns metrics in `jev/eval.py` and create-only text-denylisted result writing in `jev/guard.py`. The published SemIf runner is a frozen pattern reference and must not be modified because its provenance pins its bytes.

Graph coverage was current with no recorded gaps for the Laya agent/common/router paths, their relevant tests, the SemIf receipt pattern, and the shared Jev metric/writer seams. This is best-effort coverage, not proof of completeness.

## Design decision

Ranked alternatives for the load-bearing model path:

1. **Selected — Router-selected root English checkpoint from an exact local snapshot.** This follows the documented recommended path while making revision pinning possible despite `laya.load` lacking a revision argument.
2. Direct `Agent` on the root checkpoint. It would produce the same model path but would skip evidence that the recommended Router actually selects it for every row.
3. `laya-typed-decisions`. It may be stronger on typed workflows, but this custom question does not match Laya's opt-in workflow IDs and selecting it would be a hand-picked alternate checkpoint, not the default routed arm.
4. Raise `max_len` / `head_max_len` or shortlist. That may preserve more state, but it changes the shipped default after observing a known limitation and belongs only in a separately registered follow-up.

Strongest counterargument: the typed-decisions checkpoint is arguably the semantically closest model. The reason not to use it here is reproducibility of Laya's default recommended behavior, not a claim that the root model is Laya's best achievable scorer. The receipt must make that distinction explicit. This is the main open question for plan QA.

## Risks, rollback, and non-goals

- MPS/kernel variability is avoided by explicit CPU/float32. A CPU resource failure stops the arm rather than silently changing device or checkpoint.
- Native 512-token truncation may remove late recent-action context. That is a measured property of this default arm, not grounds to tune context length after seeing results.
- Model/source drift is controlled by full commits and snapshot/file hashes; a mismatch stops the run.
- Rollback is deletion of the additive receipt/runner/test and documentation pointers. No runtime API, schema, dependency, or production behavior changes.
- Non-goals: Laya source changes, integration adapter, tuning, calibration fitting, context-budget changes, shortlisting, alternate checkpoint/model sweep, Jev/SemIf rerun, private data, deployment, or broad capability claim.
- Any unexpected execution failure follows `/debug-mantra`: reproduce the exact row/run, trace the failing call path, run the cheapest disproof, and record every probe before changing the frozen arm.
